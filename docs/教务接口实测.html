0. 完整链路总览（App 端照此实现）

① POST https://ehallmobile.xyc.edu.cn/api/v4/api/login     （3DES 加密，见登录协议分析.md）
   → { code:"200", token, data:{ CASTGC, JSESSIONID, casUserInfo } }
   → 后续门户 API 带 Authorization: <token> 头

② GET https://zfjwxt.xyc.edu.cn/sso/xyoauthlogin?ticket=<token>
   → 302 /jwglxt/ticketlogin?uid=<学号>&timestamp=...&verify=<服务端签名>&ydType=1
   → 302 /jwglxt/xtgl/login_slogin.html（中转）
   → 302 /jwglxt/xtgl/index_initMenu.html?jsdm=xs → 200 教务首页 ✅
   → 教务域 JSESSIONID 建立（OkHttp CookieJar 自动持有）
   ★ index_initMenu 响应 HTML 内联完整菜单（clickMenu 调用，含 wapLogin 签名 key/time）

③ 业务接口：两条路径
   A) 直连：POST /jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151  {xnm, xqm}   ← 课表（最简单）
   B) WAP 签名链：GET /jwglxt/xtgl/login_wapLogin.html?procode=008&type=1
        &choice=<Y功能码>&uid=<学号>&role=xs&key=<内联签名>&time=<内联时间戳>
      → 302 对应业务移动端页面（页面内含数据接口与 pkey）

5. 已知限制与注意事项

  • wapLogin 的 key/time 签名由 index_initMenu SSR 生成，每次 SSO 后重新提取，不可复用
  • 成绩/个人信息/考试等 WAP 链接口需先 GET 对应移动端页面（Referer 校验）
  • 请求频率保持克制（每次 App 启动登录一次 + 会话失效重登；数据本地缓存优先）
  • 教务会话过期表现：302 → login_slogin.html；门户 token 过期：API code=401
